BZFlag Web Gateway

This small Node.js service translates a browser WebSocket connection into TCP and UDP connections to an allowlisted BZFlag server. It does not expose arbitrary host or port access and it does not run a BZFlag game server.

Security first: keep the gateway bound to a private interface while configuring it. Use HTTPS/WSS behind a reverse proxy for public deployments, keep a long random session token, and list only servers that you explicitly trust.

Requirements

  • Node.js 26.7.0 or a newer supported stable release.
  • Network access from this host to the selected official BZFlag server.
  • A browser client served from an origin listed in allowedOrigins.

Install and configure

After generating the random value, place it in ./config.json as sessionToken. Replace the example official host with an approved BZFlag server before starting the gateway. New browser clients carry this bearer in the WebSocket subprotocol; set allowLegacyQueryToken to false once older clients have been retired.

cd server
cp ./config.example.json ./config.json
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
npm ci
npm run build
npm start

On Windows PowerShell, use Copy-Item ./config.example.json ./config.json instead of cp. The gateway prints its listening address and token source at startup, never the bearer token itself. Set BZFLAG_WEB_SESSION_TOKEN or a private ./config.json sessionToken in production.

Check the service

curl http://127.0.0.1:8080/healthz

The WebSocket endpoint is /bridge?server=official-main. The browser offers bzflag-web-v1 together with its encoded bearer as a subprotocol, and the gateway returns Sec-WebSocket-Protocol: bzflag-web-v1. The browser client should use ws:// for local HTTP development and wss:// when its page is served over HTTPS.

Docker

docker build -t sythos/bzflag-web-gateway:local .
docker run --rm --name bzflag-web-gateway \
  -p 8080:8080 \
  -v "./config.json:/app/config.json:ro" \
  sythos/bzflag-web-gateway:local

Keep config.json outside the image so the token and allowlist are not baked into a public layer. The image contains only the gateway, not bzfs.

Reverse proxy

Terminate TLS at Apache or Nginx and forward WebSocket upgrades to the gateway. Add the public page origin exactly (including scheme and port) to allowedOrigins. Keep trustProxy disabled unless every proxy in front of this service is controlled by you, and then list each direct proxy IP exactly in trustedProxyPeers.

Future custom-server support

Configuration entries already have a kind field and can carry per-server protocol metadata. Entries marked custom remain blocked while allowCustomServers is false. This default prevents a public gateway from becoming a general-purpose TCP/UDP proxy.
